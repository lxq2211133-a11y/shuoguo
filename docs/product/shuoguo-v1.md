# 硕果研习 V1 产品方案

## 当前版本的运行方式

使用 Node.js 24，在项目目录构建并启动。

```powershell
npm run build
npm start
```

如果环境只有 Node.js，可以直接执行 `node node_modules/typescript/bin/tsc -b`、`node node_modules/vite/bin/vite.js build`，再执行 `node --env-file-if-exists=.env.local server/start.mjs`。

默认访问 `http://127.0.0.1:5174`。`npm start` 读取 `.env.local` 中的服务端 AI 配置。账号、作答、报告和图片默认写入 `.study-data/study.sqlite`。独立部署时用 `STUDY_DB_PATH` 指向持久存储，并为 HTTPS 环境设置 `STUDY_SECURE_COOKIE=1`。`/api/health` 可用于服务存活检查。开发时可使用 `npm run dev`。

教研人员先注册账号，然后由本机维护人员在同一数据库执行 `node --env-file-if-exists=.env.local scripts/grantTeachingRole.mjs <教研账号>`。重新打开页面后，从「我的备考档案」进入教研工作台。西南交大 894 可直接使用内置的 `swjtu-894-v1` 评分表。学生报告只会引用同题、同版本且已发布的案例。教研人员可以查看学生主动共享的待复核报告，并单独回传结论。

1. 收到试练原图后，先分配作品编号与用途。同一作品的初稿、改稿和重新拍摄的版本沿用编号，归入同一组。
2. 选择「标注专家案例」，录入有案例展示授权的原图，填五项分数和原图可核对的依据，再发布到案例库。
3. 选择「登记盲评作品」，录入独立留出且有内部评测授权的原图。登记后仅教研可查看。收齐样本后，由两位老师独立打分，再用相同作品对比两种评图方式。

当前验证范围包括账号隔离、理论作答和带背回流、评图报告与同题复评、教研授权及案例引用。院校和理论内容仍由项目内置资料提供。正式内测前需要按目标院校核验考试资料，由教研人员发布真实授权案例，并执行独立的老师盲评和学生试用。会员区目前展示权益说明，付费需要接入实际商户和订单流程。

## 产品定位

硕果研习是面向产品设计、工业设计考研学生的备考平台。学生设置目标院校、考试科目、备考阶段和可用时间，获得每日训练任务。完成理论练习或提交快题后，系统保存作答、反馈和待解决的问题，并据此安排下一次练习。

首版以已确定目标院校的考生为主要用户。首个试点是西南交通大学设计艺术学院 085507 工业设计工程（全日制）的 01 工业设计方向，覆盖 337 工业设计工程和 894 命题设计与专业综合能力两条训练线。试点先整理 337 参考书对应的考点，再用一套原创 894 快题跑通初评、改稿和复评。 [试点资料核验记录](../research/school-research-notes.md#西南交通大学)

## 学生端

| 入口 | 学生要完成什么 | 训练结果如何进入下一步 |
| --- | --- | --- |
| 今日 | 查看今天最值得做的任务，继续上次未完成的训练 | 根据到期带背、未完成改稿、备考阶段和可用时间给出任务，显示每项安排的原因 |
| 训练 | 完成理论回忆、做卷或快题 | 每次提交绑定题目和评分表版本，记录作答、反馈及下一步 |
| 复盘 | 回看理论薄弱考点、作品版本与快题待改项 | 从历史记录直接回到带背、同题改稿或相应专项 |
| 我的 | 管理目标院校、学习时间、账号和数据 | 切换目标后重算后续任务，历史成绩保留原院校、题目和版本 |

院校资料从首页的目标院校入口进入。按院校、科目和考试年份展示目录、考试大纲及练习资源。资料记录来源和核验日期，院校风格推断单独标明。公开资料支持的考试要求与教研训练建议分别呈现。

### 理论训练流程

到期带背或模拟卷 → 作答 → 对照参考要点自评 → 标记薄弱考点 → 自动进入后续复习。

首版使用教研审核的模拟卷和答题要点。学生交卷后能按题查看自己的答案、参考要点和关联考点，把薄弱点直接加入复习队列。记录中区分带背自评和模拟卷自评。理论考点与快题的连接通过明确的知识关联实现，例如快题反馈指出适老产品的人机尺度表达不足时，可链接到相应理论考点或专项练习。

### 快题训练流程

选择训练题 → 作画并上传 → 查看分项证据与案例 → 领取改稿任务 → 同题上传改稿 → 查看问题是否解决。

评图页优先展示本图最重要的一到三处问题。每条反馈关联评分项，标明画面位置、可观察现象和具体改法。有适用的已审核案例时，可展开查看例图、专家分项评价以及同类问题。图像模糊或关键信息不可见时，提示补拍或补传；评图失败时保留提交并允许重试。演示评图使用独立入口和演示状态。

初稿和改稿保留独立版本。学生提交改稿时勾选本轮要核对的问题。复评沿用同一题和同一评分表，逐项列出所选问题的变化依据，并把其他问题列为「本轮未核对」。分项分数仍根据整张改稿给出。复盘保留两版的评分与证据，便于追溯。反复出现的问题可以进入后续专项训练。

### 一次完整的使用示例

学生选择目标院校后，首页建议复习两张到期卡片，并继续上次的出行产品快题。他完成带背，按评分反馈在初稿右下角补上归还和锁止确认，提交改稿。复评记录流程缺项已补齐，同时发现锁止状态仍难辨认。下次进入首页，他可以继续完善这一项，并看到新的理论复习任务。

## 教研运营与评分

- **训练内容。** 教研可以维护院校资料、理论考点、模拟卷和快题，按草稿、审核、发布、下架管理。已完成的练习保留当时的题目和评分表版本。
- **评分表。** 首版沿用当前 150 分产品设计快题训练表，增加分项档位和可观察的判断条件。评估可见题目要求的满足程度。院校训练偏好随来源标注，评分表由教研审核并发布。程序校验分项、计算总分，缺失项进入复核或补充证据流程。
- **专家案例。** 统一保存授权状态、原图、题目、评分表版本、老师分项分数、评语和证据位置。先按同类题、评分项和问题标签检索，经对照验证后再扩展检索方式。学生作品经过授权、教师标注及审核后方可进入案例库。
- **人工复核。** 教研查看有争议的评分和无证据反馈，记录原结论、复核结果及原因。首版由运营处理个案，后续根据试用量扩展处理队列。

## 从原型到可用的开发顺序

| 阶段 | 可复用的现状 | 需要交付 | 验收方式 |
| --- | --- | --- | --- |
| 1. 能继续学习 | 院校切换、带背自评、本机复习记录、模拟卷与快题页面 | 账号和目标档案、服务端学习记录、作品私有存储、任务状态、首页继续学习 | 学生首次进入能建立任务，刷新或换设备可以继续；不同账号无法访问彼此的记录 |
| 2. 理论与快题都能交作业 | 理论考点、模拟卷拆题、快题要求、上传和评图服务入口 | 理论作答与自评记录、薄弱点回到带背、真实评图报告、同题改稿复评、历史页 | 理论卷自评后能复习对应考点；初稿与改稿均可回看，评图失败后可重试原提交 |
| 3. 能持续运营 | 院校来源登记、示例案例、教研后台预览 | 资料与题目发布、评分表和案例审核、人工复核、部署、失败监控与用户反馈入口 | 教研能更新一份资料并发布；通过独立评测和小范围试用后开放内测范围 |
| 4. 验证付费 | 会员权益展示 | 服务端额度与真实权益；确认付费范围后接通订单、支付与售后流程 | 成功订单可用，失败可恢复，重复回调只发放一次权益；学生能查询消耗和订单 |

前三个阶段构成 V1 内测范围。多院校扩展、手绘专项评分表、动态组卷、完整图像向量检索和商业化可以按使用数据安排。现有前端和 AI 接口可继续作为实现基础，学生记录、评分任务和内容权限由正式服务端管理。

## 验证与运营指标

- **首周训练完成率。** 已设置目标的试用学生中，七天内完成理论作答并回访复习，或完成快题初评并提交改稿复评的人数占比。两条路径分别统计。
- **关键流程。** 记录设置目标、首次提交、查看反馈、完成后续任务四个环节的转化。抽样看学生在哪里需要人工帮助，以及离开后能否接着做。
- **评分验证。** 由两位教师在独立留出的作品上按同一量表盲评，记录教师间差异。用相同模型和作品对照「评分表」与「评分表加案例」，比较总分及分项误差、证据正确率和建议可执行性。案例库与测试集按作品隔离，初稿和改稿作为同组隔离。
- **上线检查。** 通过账号隔离、上传失败可重试、历史可找回、任务状态可追溯和内容可下架的验收。对上传用途、案例授权和作品删除提供可见入口。评分有效性的目标由首轮老师盲评结果确定，试用数据和演示数据分别记录。
