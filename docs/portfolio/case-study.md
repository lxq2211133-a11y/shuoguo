# 硕果研习｜产品经理作品集案例草稿

> 状态：可交互原型，尚未发布。本文只陈述已实现的能力；用户需求、效果和商业价值仍待验证。

## 一句话介绍

硕果研习面向准备产品设计、工业设计研究生考试的考生，尝试把目标院校资料、理论复习和快题反馈放进同一条每日训练流程。

## 项目背景与本人职责（展示前补充）

请填写项目起止时间、发起原因、你本人负责的需求分析与产品决策、设计和开发的参与者，以及实际协作方式。不要把工具生成或他人完成的工作写成个人独立成果。

## 问题与目标用户（待验证假设）

首批目标用户设定为：已经确定目标院校、需要同时准备设计理论与手绘快题、难以判断每天先练什么的考生。

待验证的问题是：资料分散、复习安排靠自己记、快题反馈难转化成下一次具体练习。尚无真实访谈或使用数据证明这些问题的普遍程度，作品展示时应明确说这是产品假设。

## 我的产品判断

原型提供四所院校入口，但第一条重点流程选择“目标院校 → 今日带背 → 自评掌握程度 → 安排下次复习 → 更新首页状态”。它让用户完成一个可回访的动作，也为后续连接组卷、快题和评图留下位置。

院校风格与训练偏向可能包含推断，项目把资料分为官方、二级来源、经验和推断，并展示可信度。示例评图明确标为模拟结果，不把预设分数当成真实识图能力。

## 当前可演示的流程

1. 选择目标院校，查看相应资料、模拟卷和快题题目。
2. 从首页进入带背卡片，先独立回忆，再选“不会／模糊／熟悉”。
3. 系统分别安排 1／3／7 天后的下次复习；本机浏览器保存记录，首页展示已复习、待复习和自评熟悉的卡片数。
4. 查看理论考点与组卷拆题；使用示例评图了解评分维度和修改建议。

目前没有账号同步、真实学习成绩统计、真实支付流程或经过验证的 AI 评分准确率。浏览器清除本地数据会移除复习记录。

## 验证计划与衡量方式

先按 [用户验证计划](validation-plan.md) 完成目标考生访谈和任务测试。首轮重点看：

- 用户能否在不解释的情况下找到今天要做的任务，并完成一张带背卡片；
- 用户是否理解“熟悉／模糊／不会”如何影响下次复习；
- 用户能否区分示例评图、院校训练推断与已核实事实。

若进入真实试用阶段，再记录首次完成训练比例、复习到期后的回访比例、建议被采纳比例。当前没有这些指标的实测值。

## 后续迭代顺序

1. 根据访谈缩小目标人群，修正首页任务入口和文案。
2. 将复习记录从本机迁移到账号，并补上真实练习提交与反馈记录。
3. 请教研人员评估评图反馈的可执行性和评分一致性，再考虑开放真实 AI 评分。
4. 验证会员付费意愿和权益组合后，再设计付费转化流程。

## 作品集呈现建议

正文用“问题假设 → 关键取舍 → 原型流程 → 真实测试发现 → 修改 → 未解决问题”的顺序。附图建议选首页、带背自评前后、院校来源标注、示例评图说明。完成测试前，结果页只展示原型实现与验证计划，不使用演示运营数字充当成果。
